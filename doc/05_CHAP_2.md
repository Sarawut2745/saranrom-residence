# ทฤษฎีและเอกสารที่เกี่ยวข้อง

การพัฒนาระบบบริหารจัดการหอพักและอพาร์ตเมนต์รายเดือน เดอะ สราญรมย์ เรสซิเดนซ์ ผ่านเว็บแอปพลิเคชัน (The Saranrom Residence) จำเป็นต้องอาศัยการประยุกต์ใช้องค์ความรู้ แนวคิด ทฤษฎีทางวิศวกรรมซอฟต์แวร์ สถาปัตยกรรมระบบสารสนเทศ และเทคโนโลยีการพัฒนาเว็บแอปพลิเคชันสมัยใหม่ ตลอดจนการศึกษาทบทวนวรรณกรรมและงานวิจัยที่เกี่ยวข้อง เพื่อใช้เป็นกรอบและรากฐานในการออกแบบระบบให้มีประสิทธิภาพ ถูกต้องตามมาตรฐาน และตอบสนองความต้องการของผู้ใช้งานอย่างแท้จริง คณะผู้จัดทำได้รวบรวมเนื้อหาทฤษฎีและเอกสารที่เกี่ยวข้อง โดยแบ่งออกเป็น 7 หัวข้อหลัก ดังนี้

## 2.1 แนวคิดการบริหารจัดการหอพักและอพาร์ตเมนต์รายเดือน

การบริหารจัดการอาคารพักอาศัยรวม หอพัก และอพาร์ตเมนต์ให้เช่ารายเดือน เป็นธุรกิจการให้บริการที่เกี่ยวข้องกับกระบวนการทำงานที่หลากหลายและต่อเนื่องในแต่ละรอบเดือน (กิตติพันธ์ คงสวัสดิ์เกียรติ, 2562: 45) โดยมีกิจกรรมหลักที่สำคัญดังต่อไปนี้:

### 2.1.1 การบริหารจัดการข้อมูลห้องพักและสัญญาเช่า (Room and Contract Management)
ห้องพักเป็นทรัพยากรหลักที่สร้างรายได้ให้แก่หอพัก การบริหารจัดการสถานะห้องพักจำเป็นต้องมีความชัดเจนและเป็นปัจจุบันเสมอ โดยทั่วไปสถานะห้องพักแบ่งออกเป็น 3 สถานะหลัก ได้แก่ ห้องว่างพร้อมให้เช่า (Available), ห้องมีผู้พักอาศัย (Occupied) และห้องปิดปรับปรุงหรือซ่อมแซม (Maintenance)  
ในส่วนของสัญญาเช่า (Lease Agreement) เป็นนิติกรรมที่กำหนดสิทธิและหน้าที่ระหว่างผู้ให้เช่าและผู้เช่า โดยมีองค์ประกอบสำคัญที่ต้องบันทึก ได้แก่ วันที่เริ่มต้นสัญญา วันสิ้นสุดสัญญา วันที่เข้าพักจริง (Move-in Date) วันที่ย้ายออกจริง (Move-out Date) และเงินประกันความเสียหาย (Deposit Amount) ซึ่งข้อมูลเหล่านี้จำเป็นต้องแยกการจัดเก็บออกจากข้อมูลคุณลักษณะของห้องพัก เพื่อรองรับประวัติการเช่าหลายรอบในห้องพักเดียวกัน

### 2.1.2 การบริหารจัดการสาธารณูปโภคและการออกใบแจ้งหนี้ (Utility & Billing Management)
รายได้ของหอพักประกอบด้วยค่าเช่าห้องพักคงที่รายเดือน และค่าสาธารณูปโภคผันแปรตามการใช้งานจริง ได้แก่ ค่าน้ำประปาและค่าไฟฟ้า กระบวนการทำงานเดิมต้องใช้เจ้าหน้าที่เดินสำรวจและจดเลขมิเตอร์ในวันเดียวกันของทุกเดือน นำเลขมิเตอร์ปัจจุบันมาลบด้วยเลขมิเตอร์ครั้งก่อนหน้า เพื่อหาผลต่างจำนวนหน่วยที่ใช้จริง (Consumed Units) จากนั้นนำมาคูณด้วยอัตราค่าบริการต่อหน่วย และรวมเข้ากับค่าเช่าห้อง ค่าอินเทอร์เน็ต หรือค่าส่วนกลางอื่น ๆ เพื่อสรุปเป็นยอดเงินสุทธิที่ต้องชำระ การประยุกต์ใช้ระบบคำนวณอัตโนมัติจะช่วยลดความผิดพลาดและประหยัดเวลาได้อย่างมหาศาล

### 2.1.3 การบริหารจัดการคำร้องแจ้งซ่อมและการบำรุงรักษา (Maintenance Management)
การรักษาสภาพแวดล้อมและสิ่งอำนวยความสะดวกให้อยู่ในสภาพสมบูรณ์เป็นปัจจัยสำคัญต่อความพึงพอใจและการต่อสัญญาเช่าของผู้พักอาศัย ระบบจัดการงานซ่อมที่มีประสิทธิภาพต้องมีคุณสมบัติในการแยกหมวดหมู่งานช่าง (เช่น ระบบไฟฟ้า, ระบบประปา, เครื่องปรับอากาศ, เฟอร์นิเจอร์) การระบุระดับความเร่งด่วนของปัญหา การแนบภาพถ่ายความเสียหาย และการแจ้งความคืบหน้าระหว่างนิติบุคคล ช่าง และผู้เช่า

## 2.2 วงจรการพัฒนาระบบและระเบียบวิธีพัฒนาซอฟต์แวร์

### 2.2.1 วงจรการพัฒนาระบบ (System Development Life Cycle: SDLC)
วงจรการพัฒนาระบบเป็นกระบวนการทางวิศวกรรมที่ใช้ในการสร้างและปรับปรุงระบบสารสนเทศให้มีคุณภาพ เสร็จตามกำหนดเวลา และตรงตามงบประมาณ (Dennis, Wixom and Roth, 2018: 12) ประกอบด้วยระยะสำคัญ 5 ระยะ ได้แก่:
1. การวางแผนโครงการ (Planning Phase)
2. การวิเคราะห์ระบบและความต้องการ (Analysis Phase)
3. การออกแบบระบบเชิงตรรกะและกายภาพ (Design Phase)
4. การพัฒนาระบบและเขียนรหัสต้นฉบับ (Implementation Phase)
5. การทดสอบ บำรุงรักษา และประเมินผล (Testing and Maintenance Phase)

### 2.2.2 ระเบียบวิธีพัฒนาซอฟต์แวร์เชิงคล่องตัว (Agile Methodology)
ในการพัฒนาเว็บแอปพลิเคชันสมัยใหม่ที่มีการเปลี่ยนแปลงความต้องการได้อย่างต่อเนื่อง ระเบียบวิธีแบบ Agile ได้รับความนิยมมากกว่าแบบเดิม (Waterfall Model) เนื่องจากเน้นการส่งมอบชิ้นงานที่ใช้งานได้จริงในรอบการทำงานระยะสั้น (Sprints) มีการประสานงานร่วมกันอย่างใกล้ชิด และเปิดรับข้อเสนอแนะเพื่อนำมาปรับปรุงระบบได้อย่างยืดหยุ่น โครงงานนี้เลือกใช้แนวคิด Agile เพื่อให้สามารถปรับปรุงฟังก์ชันการใช้งานตามคำแนะนำของเจ้าของหอพักและผู้เช่าได้อย่างต่อเนื่อง

## 2.3 สถาปัตยกรรมและเทคโนโลยีการพัฒนาเว็บแอปพลิเคชัน

### 2.3.1 สถาปัตยกรรมเว็บแอปพลิเคชันยุคใหม่ (Modern Web Application Architecture)
วิวัฒนาการของเว็บแอปพลิเคชันได้พัฒนาจากสถาปัตยกรรม Client-Server แบบดั้งเดิม สู่ Single Page Application (SPA) และเข้าสู่ยุค Hybrid Rendering ที่ผสมผสานระหว่าง Server-Side Rendering (SSR) และ Static Site Generation (SSG)  
การประมวลผลบนเซิร์ฟเวอร์ (Server-Side Rendering) มีข้อได้เปรียบอย่างยิ่งในด้านความปลอดภัย การซ่อนโค้ดและข้อมูลสำคัญ การเพิ่มประสิทธิภาพในการค้นหาผ่าน Search Engine (Search Engine Optimization: SEO) และความเร็วในการแสดงผลครั้งแรก (First Contentful Paint: FCP) บนอุปกรณ์ที่มีขีดความสามารถจำกัด

### 2.3.2 React 19 และ React Server Components (RSC)
React เป็นไลบรารี JavaScript ยอดนิยมสำหรับการสร้างส่วนติดต่อผู้ใช้ที่พัฒนาโดยบริษัท Meta ในเวอร์ชัน 19 ได้เปิดตัวแนวคิด React Server Components (RSC) อย่างเป็นทางการ ซึ่งอนุญาตให้คอมโพเนนต์สามารถประมวลผลและดึงข้อมูลจากฐานข้อมูลได้โดยตรงบนเซิร์ฟเวอร์ โดยไม่ต้องส่งโค้ด JavaScript ที่ไม่จำเป็นไปยังเว็บบราวเซอร์ของไคลเอนต์ ส่งผลให้ขนาดของ Bundle มีขนาดเล็กลงอย่างมาก และลดปัญหาเวลาตอบสนองของระบบ (Latency)

### 2.3.3 Next.js Framework เวอร์ชัน 15
Next.js พัฒนาโดยบริษัท Vercel เป็นเฟรมเวิร์กมาตรฐานระดับองค์กรสำหรับการพัฒนาเว็บแอปพลิเคชันด้วย React (Vercel, 2024: online) โดยในเวอร์ชัน 15 ได้นำเสนอโครงสร้าง App Router ที่มีคุณลักษณะเด่นดังนี้:
1. **File-system Based Routing**: การกำหนดเส้นทางหน้าเว็บอัตโนมัติตามโครงสร้างโฟลเดอร์และไฟล์ในโฟลเดอร์ `app/` เช่น `app/rental/bills/page.tsx` จะแปลงเป็น URL `/rental/bills`
2. **Server Actions & Route Handlers**: ความสามารถในการเขียนฟังก์ชันประมวลผลฝั่งเซิร์ฟเวอร์ที่ปลอดภัย โดยไม่ต้องเขียน API แยกต่างหาก
3. **Layout & Template Inheritance**: รองรับการสืบทอดโครงสร้างเลย์เอาต์ (Nested Layouts) ทำให้สามารถสร้างส่วนหัว (Navbar) แถบด้านข้าง (Sidebar) และส่วนท้าย (Footer) ที่คงสถานะไว้ได้โดยไม่ต้องเรนเดอร์ใหม่ทั้งหน้า
4. **Route Groups**: การจัดหมวดหมู่เส้นทางโดยใช้วงเล็บ เช่น `(visitor)`, `(rental)`, `(staff)` ช่วยให้โค้ดเป็นระเบียบโดยไม่ส่งผลต่อเส้นทาง URL จริง

### 2.3.4 ภาษา TypeScript เวอร์ชัน 5
ภาษา TypeScript พัฒนาโดยบริษัท Microsoft เป็นส่วนขยายแบบพิมพ์เขียวเข้มงวด (Strictly Typed Superset) ของภาษา JavaScript (Hejlsberg, 2023: 18) มีข้อดีที่สำคัญต่อการพัฒนาระบบขนาดใหญ่ดังนี้:
1. **Static Type Checking**: การตรวจสอบความถูกต้องของประเภทข้อมูลตั้งแต่ขั้นตอนการเขียนโค้ด (Compile-time) ป้องกันข้อผิดพลาดประเภท `TypeError: Cannot read properties of undefined`
2. **Enhanced Developer Experience (DX)**: รองรับการทำงานร่วมกับ IDE อัจฉริยะ การเติมโค้ดอัตโนมัติ (IntelliSense) และการตรวจจับชนิดข้อมูลของฐานข้อมูลโดยตรง
3. **Maintainability**: ช่วยให้การปรับปรุงโครงสร้างโค้ด (Refactoring) มีความปลอดภัยและเป็นระบบ

### 2.3.5 การจัดสไตล์ด้วย Vanilla CSS, Scoped CSS Modules และ Design System
ในการพัฒนาซอฟต์แวร์ที่ต้องการความยืดหยุ่น การควบคุมระดับสูง และประสิทธิภาพสูงสุด การใช้ Vanilla CSS ร่วมกับ Scoped CSS Modules ช่วยลดภาระในการคอมไพล์ของเครื่องมือภายนอก และทำให้ไฟล์สไตล์มีขนาดกะทัดรัด  
หลักการออกแบบของระบบ The Saranrom Residence ยึดถือแนวทาง **Modern Minimalist Premium Design**:
- การใช้คู่สีสุขุม (Tailored HSL Color Palette) ได้แก่ สีน้ำเงินเข้มเนวีบลู (Slate Navy), สีเทาสะอาดตา (Neutral Gray) และสีทองอำพันสำหรับจุดเน้น (Accent Amber)
- ปราศจากการใช้อิโมจิ (No Emoji Policy) โดยใช้ชุดไอคอนมาตรฐานสากลจาก Lucide React เพื่อรักษาภาพลักษณ์ความเป็นทางการและน่าเชื่อถือ
- การกำหนดตัวแปร CSS Custom Properties สำหรับ Design Tokens เพื่อความสม่ำเสมอของระยะห่าง (Spacing), รัศมีความโค้ง (Border Radius) และเงา (Box Shadow)

## 2.4 ระบบจัดการฐานข้อมูลและการรักษาความปลอดภัย

### 2.4.1 ระบบจัดการฐานข้อมูลเชิงสัมพันธ์ PostgreSQL
PostgreSQL เป็นระบบจัดการฐานข้อมูลเชิงสัมพันธ์แบบวัตถุ (Object-Relational Database Management System: ORDBMS) แบบโอเพนซอร์สที่มีความเสถียร มีความน่าเชื่อถือ และเป็นไปตามมาตรฐาน ACID (Atomicity, Consistency, Isolation, Durability) สูงที่สุด (Momjian, 2021: 88) มีจุดเด่นด้านการรองรับข้อมูลหลากหลายประเภท เช่น JSONB, UUID, คอลัมน์คำนวณอัตโนมัติ (Generated Stored Columns) และการทำดัชนีขั้นสูง (Advanced Indexing)

### 2.4.2 แพลตฟอร์ม Supabase (Backend-as-a-Service: BaaS)
Supabase เป็นแพลตฟอร์มทางเลือกโอเพนซอร์สของ Firebase ที่สร้างขึ้นบนโครงสร้างพื้นฐานของ PostgreSQL อย่างแท้จริง (Supabase Inc, 2024: online) ให้บริการส่วนสำคัญในการพัฒนาดังนี้:
1. **Database Service**: บริการฐานข้อมูล PostgreSQL บนคลาวด์ พร้อมส่วนจัดการ SQL Editor และ Schema Designer
2. **Supabase Auth**: ระบบการยืนยันตัวตนผู้ใช้ระดับองค์กร รองรับการล็อกอินด้วยอีเมล-รหัสผ่าน การจัดการเซสชันแบบคุกกี้ (SSR Cookie Auth) ผ่านไลบรารี `@supabase/ssr`
3. **Supabase Storage**: พื้นที่จัดเก็บไฟล์อ็อบเจกต์ (Object Storage) สำหรับจัดเก็บภาพถ่ายสลิปการโอนเงิน เอกสาร และรูปภาพหน้าแรกของเว็บไซต์
4. **Database Functions & Triggers**: การเขียนฟังก์ชัน SQL เพื่อการประมวลผลข้อมูลอัตโนมัติที่ปลอดภัยและมีประสิทธิภาพ

### 2.4.3 กลไกความปลอดภัย Row Level Security (RLS) และ Role-Based Access Control (RBAC)
ในระบบฐานข้อมูลดั้งเดิม สิทธิ์การเข้าถึงข้อมูลมักถูกตรวจสอบในระดับแอปพลิเคชัน (Application Layer) ซึ่งเสี่ยงต่อการที่นักพัฒนาจะลืมใส่เงื่อนไขกรองข้อมูล แต่ใน PostgreSQL และ Supabase มีฟังก์ชัน **Row Level Security (RLS)** ซึ่งเป็นกลไกตรวจสอบความปลอดภัยในระดับเครื่องมือฐานข้อมูล (Database Engine Layer)  
การทำงานของ RLS ร่วมกับ RBAC ช่วยรับประกันว่า:
- ผู้เช่าแต่ละคนจะสามารถมองเห็นเฉพาะข้อมูลบิล สัญญาเช่า และคำร้องแจ้งซ่อมของห้องพักตนเองเท่านั้น แม้จะเกิดข้อผิดพลาดในการเขียนโค้ดฝั่งหน้าเว็บก็ตาม
- เจ้าหน้าที่นิติบุคคลและเจ้าของหอพักเท่านั้นที่มีสิทธิ์เข้าถึงข้อมูลรวมของทุกห้องพัก และมีสิทธิ์อนุมัติสลิปหรือจัดการผังห้อง

## 2.5 เทคโนโลยีระบบการชำระเงินดิจิทัลและเอกสารอิเล็กทรอนิกส์

### 2.5.1 มาตรฐาน Thai QR Payment (PromptPay) และแนวคิด Manual Slip Verification
การชำระเงินผ่านระบบพร้อมเพย์ (PromptPay) อ้างอิงตามมาตรฐาน EMVCo QR Code Specification ที่กำหนดโดยธนาคารแห่งประเทศไทยและสมาคมธนาคารไทย ช่วยให้ผู้ชำระเงินสามารถสแกนบาร์โค้ด 2 มิติเพื่อโอนเงินผ่านระบบเครือข่ายพร้อมเพย์ได้อย่างถูกต้องตามยอดเงินที่ระบุ (ธนาคารแห่งประเทศไทย, 2561: 15)  
สำหรับระบบของหอพักเดอะ สราญรมย์ เรสซิเดนซ์ ได้เลือกใช้แนวทางการตรวจสอบสลิปโดยเจ้าหน้าที่ (Manual Slip Verification) แทนการเชื่อมต่อระบบ Payment Gateway อัตโนมัติ เนื่องจาก:
1. หอพักเป็นธุรกิจเฉพาะกลุ่มที่มีปริมาณธุรกรรมรายเดือนในระดับที่เจ้าหน้าที่สามารถตรวจสอบได้ (ประมาณเดือนละ 1 ครั้งต่อ 1 ห้องพัก)
2. การใช้ Payment Gateway มีค่าธรรมเนียมการทำธุรกรรม (Transaction Fee 1.5% - 3.0%) ซึ่งเป็นภาระค่าใช้จ่ายต่อผู้ประกอบการหอพัก
3. การออกแบบขั้นตอนบังคับให้ผู้เช่าต้องอัปโหลดสลิปหลักฐานทุกครั้ง และกำหนดให้เจ้าหน้าที่ตรวจสอบความถูกต้องก่อนปรับสถานะบิลเป็น "ชำระแล้ว" ช่วยป้องกันการทุจริต ยอดเงินไม่ตรง หรือการแอบอ้างสลิปได้อย่างรัดกุม 100%

### 2.5.2 การสร้างเอกสารทางการในรูปแบบ PDF ด้วย Puppeteer Core
ใบแจ้งหนี้และใบเสร็จรับเงินเป็นเอกสารทางกฎหมายและการบัญชีที่จำเป็นต้องมีรูปแบบที่แน่นอน ไม่คลาดเคลื่อนตามขนาดหน้าจอหรือเบราว์เซอร์ของผู้ใช้ การเลือกใช้ Puppeteer Core ซึ่งเป็นเครื่องมือควบคุม Headless Chrome Browser ช่วยเรนเดอร์หน้าเว็บ HTML/CSS คุณภาพสูงให้ออกมาเป็นไฟล์ PDF ที่คมชัดระดับสิ่งพิมพ์ พร้อมสั่งพิมพ์หรือดาวน์โหลดเก็บไว้เป็นหลักฐานได้ทันที

### 2.5.3 การแจ้งเตือนผ่าน LINE Official Account (LINE Messaging API)
LINE เป็นแพลตฟอร์มการสื่อสารยอดนิยมอันดับหนึ่งในประเทศไทย การนำ LINE Official Account และ LINE Messaging API มาเชื่อมโยงกับระบบหอพัก ช่วยให้นิติบุคคลสามารถส่งข้อความแจ้งเตือนเมื่อมีประกาศสำคัญ ข่าวสารเร่งด่วน หรือแจ้งเตือนครบกำหนดชำระเงินไปยังสมาร์ตโฟนของผู้เช่าได้โดยตรงและรวดเร็ว

## 2.6 เครื่องมือและมาตรฐานการออกแบบเชิงภาพ

### 2.6.1 ภาษามาตรฐานสำหรับการจำลองระบบ (Unified Modeling Language: UML)
UML เป็นภาษาสัญลักษณ์มาตรฐานสากลที่ใช้ในการจำลอง อธิบาย ระบุ และสร้างเอกสารสำหรับระบบซอฟต์แวร์เชิงวัตถุ (Booch, Rumbaugh and Jacobson, 2005: 55) ในโครงงานนี้ได้นำไดอะแกรม UML มาใช้งานดังนี้:
1. **Use Case Diagram**: แผนภาพแสดงปฏิสัมพันธ์ระหว่างผู้ใช้งาน (Actors) กับหน้าที่ต่าง ๆ ของระบบ (Use Cases) เพื่อกำหนดขอบเขตฟังก์ชันการทำงาน
2. **Activity Diagram**: แผนภาพแสดงลำดับขั้นตอนการทำงาน (Workflow) และเงื่อนไขการตัดสินใจในแต่ละกระบวนการธุรกิจ
3. **Sequence Diagram**: แผนภาพแสดงการส่งข้อความและลำดับเวลาในการมีปฏิสัมพันธ์ระหว่างอ็อบเจกต์ในระบบ

### 2.6.2 แผนภาพความสัมพันธ์ของเอนทิตี (Entity Relationship Diagram: ERD)
ERD เป็นเครื่องมือจำลองโครงสร้างข้อมูลเชิงแนวคิด (Conceptual Data Model) ที่แสดงถึงเอนทิตี (Entities), คุณลักษณะ (Attributes) และความสัมพันธ์ระหว่างเอนทิตี (Relationships) เช่น ความสัมพันธ์แบบหนึ่งต่อหนึ่ง (1:1) และแบบหนึ่งต่อกลุ่ม (1:N) เพื่อนำไปสู่การแปลงเป็นโครงสร้างตาราง (Physical Schema) ในระบบจัดการฐานข้อมูลเชิงสัมพันธ์ได้อย่างถูกต้องตามหลักการ Normalization

## 2.7 งานวิจัยและโครงงานที่เกี่ยวข้อง

จากการสืบค้นและศึกษาผลงานวิจัย โครงงาน และบทความวิชาการที่เกี่ยวข้องกับการพัฒนาระบบบริหารจัดการหอพักและอาคารพักอาศัย คณะผู้จัดทำได้สรุปสาระสำคัญของงานวิจัยที่เกี่ยวข้อง ดังนี้:

สมเกียรติ สว่างวงศ์ และธนพล ฤทธิเดช (2563: 112 - 120) ได้พัฒนาระบบบริหารจัดการหอพักผ่านเว็บแอปพลิเคชัน กรณีศึกษาหอพักเกษมสุข โดยใช้ภาษา PHP และฐานข้อมูล MySQL ระบบมีฟังก์ชันการจองห้องพัก การบันทึกสัญญาเช่า และการคำนวณค่าน้ำ-ค่าไฟ ผลการวิจัยพบว่าระบบช่วยลดเวลาในการออกใบเสร็จรับเงินลงได้ร้อยละ 65 แต่ยังมีข้อจำกัดในเรื่องการแสดงผลบนอุปกรณ์เคลื่อนที่ และระบบไม่มีกลไกให้ผู้เช่าอัปโหลดหลักฐานการชำระเงินผ่านระบบ ทำให้เจ้าหน้าที่ยังคงต้องตรวจสลิปผ่านกระดาษหรือแอปพลิเคชันภายนอก

ชญานิษฐ์ วัฒนสมบูรณ์ (2564: 78 - 86) ได้ศึกษาและพัฒนาระบบสารสนเทศเพื่อการจัดการห้องพักรายเดือนผ่านแอปพลิเคชันไลน์บอท (LINE Chatbot) พบว่าการสื่อสารผ่าน LINE Bot ช่วยให้ผู้เช่าเข้าถึงยอดค้างชำระได้สะดวกยิ่งขึ้น อย่างไรก็ตาม ข้อจำกัดของแอปพลิเคชันแชตคือไม่สามารถจัดการผังห้องพักเชิงภาพ (Visual Room Grid) และไม่สามารถออกรายงานสรุปทางการเงินเชิงลึกสำหรับเจ้าของกิจการได้อย่างสะดวก

ภานุวัฒน์ ประกายเกียรติ และคณะ (2565: 201 - 210) ได้พัฒนาระบบจัดการอพาร์ตเมนต์อัจฉริยะด้วยเฟรมเวิร์ก Node.js และ React ระบบมีจุดเด่นในการนำเสนอแดชบอร์ดที่ทันสมัย และมีระบบแจ้งซ่อมแซมห้องพักผ่านหน้าเว็บ ผลการทดสอบความพึงพอใจอยู่ในระดับดีมาก (ค่าเฉลี่ย 4.45 จาก 5.00) แต่งานวิจัยยังไม่มีระบบควบคุมสิทธิ์ระดับแถวข้อมูล (RLS) ทำให้ต้องเขียนโค้ดตรวจสอบความปลอดภัยในระดับ Controller ซึ่งอาจเกิดช่องโหว่ด้านความปลอดภัยของข้อมูลส่วนบุคคลได้หากระบบมีขนาดใหญ่ขึ้น

Chaisiri and Wongkham (2023: 34 - 42) ได้นำเสนอการประยุกต์ใช้สถาปัตยกรรม Serverless และ Backend-as-a-Service สำหรับระบบบริหารจัดการอาคารพักอาศัย โดยศึกษาเปรียบเทียบประสิทธิภาพระหว่างการตั้งฐานข้อมูลแบบดั้งเดิมกับการใช้ PostgreSQL บนคลาวด์ ผลการทดลองชี้ให้เห็นว่าการใช้บริการ BaaS ช่วยลดต้นทุนในการดูแลรักษาเซิร์ฟเวอร์ลงได้ถึงร้อยละ 40 และลดเวลาตอบสนองของระบบในการออกใบแจ้งหนี้แบบ Batch ได้อย่างมีนัยสำคัญ
